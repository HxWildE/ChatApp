JWT Authentication Flow (Login → Every Request)
Q: "How does your authentication work? Explain JWT."
🔴 Must Know 
sequenceDiagram
    autonumber
    actor User as User
    participant FE as React Frontend
    participant API as Express Server
    participant DB as MongoDB

    rect rgba(30, 58, 138, 0.15)
    Note over User,DB: PHASE 1 - LOGIN (happens once)
    User->>FE: Enter email + password
    FE->>API: POST /api/auth/login
    API->>API: Zod loginSchema.safeParse()
    API->>DB: User.findOne({ email })
    DB-->>API: User doc (with hashed password)
    API->>API: bcrypt.compare(password, hash)
    API->>API: jwt.sign({ userId }, SECRET)
    API-->>FE: { token: "eyJhb...", userData }
    FE->>FE: localStorage.setItem("token", token)
    FE->>FE: axios.defaults.headers["token"] = token
    FE->>FE: connectSocket(userData)
    end

    rect rgba(5, 150, 105, 0.12)
    Note over User,DB: PHASE 2 - EVERY REQUEST (automatic)
    User->>FE: Any action (send msg, etc)
    FE->>API: Request + header { token: "eyJhb..." }
    API->>API: protectRoute: jwt.verify(token, SECRET)
    API->>DB: User.findById(decoded.userId)
    DB-->>API: User document
    API->>API: req.user = user, next()
    API-->>FE: Protected response
    end

JWT Token Anatomy

eyJhbGci... . eyJ1c2VySWQi... . SflKxwRJ...

= Header (algorithm) . Payload (userId — base64, NOT encrypted!) . Signature (HMAC-SHA256)

⚠️ JWT is SIGNED, not ENCRYPTED. Anyone can decode the payload. Never put passwords/SSN in it. The signature only proves it wasn't tampered with.

Send Message — E2E Dual Delivery Path
Q: "Walk me through what happens when User A sends a message to User B."
🔴 Must Know 
sequenceDiagram
    autonumber
    actor A as User A (Sender)
    participant FE_A as React A
    participant API as Express API
    participant DB as MongoDB
    participant SOCK as Socket.IO
    participant FE_B as React B
    actor B as User B (Receiver)

    A->>FE_A: Type "Hello", click Send
    FE_A->>SOCK: emit("stopTyping")
    FE_A->>FE_A: setInput("")
    FE_A->>API: POST /api/messages/send/:B_id
    Note over FE_A,API: JWT in header, {text:"Hello"} in body
    API->>API: protectRoute -> jwt.verify
    API->>DB: Message.create({sender:A, receiver:B, text})
    DB-->>API: Saved message doc

    par HTTP Response to Sender
        API-->>FE_A: {success: true, newMessage}
        FE_A->>FE_A: setMessages(prev => [...prev, msg])
        FE_A-->>A: "Hello" appears in chat
    and WebSocket Push to Receiver
        API->>SOCK: userSocketMap[B_id] -> socketId
        SOCK->>FE_B: emit("newMessage", msg)
        alt B has A's chat open
            FE_B->>FE_B: setMessages(prev => [...prev, msg])
            FE_B->>API: markSeen(msg._id)
            FE_B-->>B: "Hello" appears in chat
        else B chatting with someone else
            FE_B->>FE_B: unseenMessages[A_id] += 1
            FE_B-->>B: Badge "1" on A's sidebar
        end
    end

The Critical Insight

Sender gets the message via HTTP response. Receiver gets it via WebSocket push. Two completely different delivery mechanisms, both updating the same messages[] state array.

Why http.createServer(app)?

Socket.IO needs the raw HTTP server object to intercept the WebSocket upgrade handshake. app.listen() creates its own internal server you can't access.

08
Typing Indicator — Debounce + Socket
Q: "How does the typing indicator work? What's the debounce logic?"
🟡 High 
sequenceDiagram
    autonumber
    actor A as User A (Typing)
    participant FE_A as ChatContainer A
    participant REF as useRef(timer)
    participant SOCK as Socket.IO
    participant FE_B as ChatContainer B
    actor B as User B

    A->>FE_A: Types "H"
    FE_A->>SOCK: emit("typing", {receiverId: B})
    SOCK->>FE_B: emit("typing", {senderId: A})
    FE_B->>FE_B: setIsTyping(true)
    FE_B-->>B: "typing..." shows
    FE_A->>REF: setTimeout(stop, 1500ms)

    A->>FE_A: Types "e" (400ms later)
    FE_A->>SOCK: emit("typing") again
    FE_A->>REF: clearTimeout(old), setTimeout(stop, 1500ms)

    A->>FE_A: Types "y" (300ms later)
    FE_A->>REF: clearTimeout, setTimeout RESET

    Note over A,B: User STOPS typing for 1500ms

    REF->>FE_A: Timer fires
    FE_A->>SOCK: emit("stopTyping", {receiverId: B})
    SOCK->>FE_B: emit("stopTyping", {senderId: A})
    FE_B->>FE_B: setIsTyping(false)
    FE_B-->>B: "typing..." disappears

Why useRef not useState?

useRef stores the timeout ID without causing re-renders. useState would trigger a re-render on every keystroke just to track a timer the user never sees — infinite render loop risk.

useEffect cleanup: return () => socket.off("typing", handler) prevents "ghost typing" when switching chats.

Two Paths

If the sender's chat is already open → message goes directly into the conversation and gets marked seen. If user is chatting with someone else → counter increments and badge shows. Clicking the user resets badge and marks all messages seen in DB.

Zod Server-Side Validation Pipeline
Q: "How do you validate user input on the server?"
🟢 Good to Know 
flowchart TD
    A["POST /api/auth/signup
{email, fullName, password, bio}"] --> B["Express: req.body"]
    B --> C["signupSchema.safeParse(req.body)"]
    C --> D{"result.success?"}

    D -->|"Invalid"| E["Return error:
result.error.errors[0].message"]
    E --> F["Example:
'Password must be at least 6 characters'"]

    D -->|"Valid"| G["Destructure validated data:
{fullName, email, password, bio}
= result.data"]
    G --> H["Check email uniqueness"]
    H --> I["bcrypt.hash(password)"]
    I --> J["User.create() in MongoDB"]
    J --> K["Generate JWT"]
    K --> L["Response: {token, userData}"]

Why safeParse not parse?

parse() throws a ZodError → needs try-catch. safeParse() returns {success, data, error} → cleaner control flow, no exceptions for expected invalid input.
